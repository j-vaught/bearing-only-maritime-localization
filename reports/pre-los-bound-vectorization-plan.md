# Pre-LOS bound vectorization and reuse plan

## Evidence reviewed

The existing candidate-specific profile records a 255-candidate comparison. Direct exact scoring took 17.906 seconds. The screened path took 32.632 seconds, comprising 12.224 seconds for target preparation, 3.223 seconds for bound calculation, and 17.133 seconds for exact fallback. It proposed 34 prunes, each later checked against exact scoring. These are shared-host diagnostic timings, not clean performance claims. The profile reports stage totals and candidate dispositions, but it does not report per-operation counts for geodesic queries, likelihood construction, grouping, or allocation. The plan below therefore identifies repeated work from source, without attributing a measured fraction of the 15.4-second overhead to any one operation.

The clearest repeated cost is in `pre_los_catalog_row_min_bound`. For a supported candidate it builds likelihood costs once with no predicted targets, again with a dummy target to recover clutter, and then once for every record and each candidate uncertainty value. The number of likelihood calls is therefore two plus the sum of the per-record uncertainty-variant counts for ordinary nonempty reports. Each call re-extracts measurement bearings, types, and sigmas, normalizes types, allocates residual and sigma arrays, and constructs a matched-cost matrix. The nested uncertainty loop and its matrix extraction are in `bearing_localization/search/pre_los_bound.py` around lines 132–164. The canonical scalar likelihood work is in `bearing_localization/search/likelihood.py`.

Two avoidable catalog/group costs are visible in the same bound. The code locates each record's component by scanning every component and checking membership, then rebuilds the set of known uncertainties by scanning that component for every representative. For one large angular component, these operations can approach quadratic work in the number of members. A single `component_by_key` map and one sorted uncertainty tuple per component remove those repeated scans without changing the uncertainty set.

The preparation stage also computes exact candidate-to-catalog geodesics and allocates one `PreLOSTargetRecord` per in-range physical record. If a candidate is not pruned, the exact scorer queries the same candidate and recomputes those geometries before its line-of-sight and scoring work. The preparation source uses the scorer's exact spatial query in `bearing_localization/search/pre_los_preparation.py` around lines 228–290. This duplication is avoidable only through a separate, provenance-checked exact-scoring entry point that consumes the already prepared records, applies the same line-of-sight operation, and preserves all exact status rules. It is a larger integration than the bound-only matrix batching and should be evaluated after that first change.

The prepared map identity is already cached per scorer in `pre_los_preparation.py` around lines 156–188. Per-candidate certification still constructs a convex hull, and bound consumption canonicalizes and sorts the target-key/coordinate pairs again. Map parsing and hashing are not repeated after the cache is populated. A later safe improvement can store the canonical target tuple in the factory-minted bundle and expose a typed binding check that compares the tuple and prepared map identity without rebuilding and sorting the same pairs. It must retain the existing exact candidate and complete target-set checks.

## Proposed repair

The first implementation should preserve the scalar formula and batch its canonical likelihood inputs. Build one flat list of all exact variants $(j,U)$ required by the existing uncertainty rule. Repeat each representative's actual bearing and normalized type for its variants, compute each exact predicted sigma as `degrees(atan2(U, range_m))`, and record the owning representative index. Pass the complete variant list to one call to `build_likelihood_costs`. For each report and representative, reduce the matched costs over only that representative's variant columns. The resulting edge floor matrix, report-wise clutter minimum, baseline, row terms, and final downward-rounded bound use the same values and operations as the current scalar loop.

This batching removes per-variant likelihood setup and repeated measurement parsing while leaving the canonical likelihood implementation unchanged. It is the lowest-risk first step because the same function still computes every wrapped-mixture and type cost. It does not eliminate the inner report-by-variant cost loop inside `build_likelihood_costs`; it removes redundant call and array setup around that loop.

The empty-prediction call already returns the exact per-report clutter-cost vector. Reuse `empty.report_clutter_costs[0]` when there is at least one report instead of making a second dummy-target call. Preserve the current explicit zero-report clutter calculation. This removes one full likelihood construction per candidate without approximating the objective.

The component and uncertainty preparation should be linear in the record count plus the number of distinct uncertainty variants. Build `component_by_key` once, and build a sorted known-uncertainty sequence per component once. For a representative with known uncertainty $U_j$, select only the pre-existing allowed values at least $U_j$; for an unknown representative, retain the existing set containing zero and each known component uncertainty. Do not infer monotonicity of the wrapped mixture in sigma, discard any currently admitted uncertainty value, or alter the representative rule.

A second-stage improvement can add a prepared likelihood-input context for a fixed measurement/configuration pair. It should be created once for a scorer and bind the exact immutable measurements and configuration. It may cache validated report arrays, normalized observation types, and exact baseline/clutter constants. To avoid maintaining a second likelihood definition, either extend the canonical likelihood routine with an internal prepared-input parameter or add an internal prepared-matrix helper that shares its scalar likelihood kernels. The public exact scoring path should continue to use the same canonical implementation. This stage should follow the first batched version and its parity results.

A separate exact-scoring reuse experiment can pass the factory-minted pre-LOS records into candidate scoring after validating scorer, measurement, configuration, candidate, and map bindings. It must run the same LOS checks on the same target coordinates, preserve unsupported-model and unknown-coverage behavior, then apply the same angular grouping, representative selection, uncertainty, likelihood, and assignment. It must fall back to the existing scorer whenever preparation is unresolved. This change touches `bearing_localization/search/pre_los_preparation.py` and `bearing_localization/search/scoring.py`, so it should be reviewed as a distinct change rather than folded into the bound batch patch.

## Future file ownership

The first bound-only patch should change `bearing_localization/search/pre_los_bound.py` and `tests/accuracy/test_a21_pre_los.py`. If prepared measurement arrays are introduced, the owning patch should also update `bearing_localization/search/likelihood.py` and add parity tests for that helper. The geodesic reuse experiment should be owned separately across `bearing_localization/search/pre_los_preparation.py`, `bearing_localization/search/scoring.py`, and focused scorer-parity tests. It should not alter the search controller or candidate ordering.

## Required correctness checks

Keep the current scalar construction as a test reference until the batched result is approved. For every fixture, compare the complete edge-floor matrix, baseline, clutter, per-row terms, raw row-min score, downward margin, and final bound. Because the first-stage approach calls the same canonical likelihood routine with the same variant columns, expect bitwise-equal edge costs where array ordering is identical; otherwise require differences smaller than the already applied numerical margin and prove the returned batch bound remains below every independent exact assignment score.

The small exhaustive suite should enumerate every clear/blocked subset for up to five catalog records and use the independent injective-assignment oracle. It should include a north-crossing component, duplicate coordinates and representative ties, mixed hard types, multiple distinct member uncertainties, an unknown representative uncertainty, heteroscedastic reports, sigma-floor behavior, zero range with zero uncertainty, and negative matched costs. It should cover more possible groups than reports and more reports than groups.

Unsupported and unresolved behavior must remain exact. Unknown coverage, a nonwater candidate, an unsupported nearby feature model, non-diagonal observation covariance, common bearing bias, zero clutter intensity, and a mismatched bundle must still yield no bound. A candidate with unresolved LOS or model coverage must use exact fallback in any future caller. The vectorized path must preserve every admitted uncertainty possibility and the original complete physical catalog binding.

The pruning comparison must retain the strict rule that a candidate is rejected only when its lower bound is greater than the exact feasible incumbent plus the existing comparison margin. Add cases immediately below, equal to, and above that boundary. Equal-score candidates and candidates within the configured tie band must remain eligible. Preserve negative costs and the current scale-aware downward bound margin; do not clamp costs or substitute a guessed floor.

No timing, profile, or candidate run is part of this plan. Once the canonical benchmark lock is free, measure the batched implementation against the same frozen sample and report target preparation, bound calculation, exact fallback, valid prune count, and complete score/tie parity separately. Record the operation counts for geodesic queries, likelihood-matrix calls, variant columns, and component members so the next optimization is driven by measured work rather than guessed attribution.

## Incumbent quality

A better exact feasible incumbent can improve the prune fraction without a heuristic. The prune condition is $L(c) > U + m$, where $L(c)$ is the certified candidate lower bound, $U$ is the score of a validated feasible candidate, and $m$ is the comparison margin. Lowering $U$ lowers the threshold, so more candidates may satisfy the same strict inequality. This changes only the cutoff, not the bound. It does not reduce the cost of preparing or bounding each candidate, and it cannot be claimed to help until the candidate is exactly scored and the same finite-domain parity checks pass.
