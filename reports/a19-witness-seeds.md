# A19 witness-seed refinement

The optional continuous seed generator refines only cells already selected by the geodesic wedge. It consumes each proposal's complete witness_report_keys graph and forms pairs only across distinct report indices. It does not cap source or neighbor lists. Proposal sequence is preserved so the caller's ranking controls which candidates receive limited pair or seed budgets. Report indices and catalog keys inside each proposal are canonicalized, so a proposal's seed IDs remain stable when those graph inputs are shuffled.

The API is generate_continuous_witness_seeds(observations, catalog, selected_proposals, *, frame, cell_size_m, max_range_m, max_pair_evaluations, max_candidate_seeds, cell_tolerance_m=1e-6, min_crossing_angle_deg=0.05, range_tolerance_m=1e-9) -> WitnessSeedResult. Pair totals are computed from report-pair key-count products. Pair records are generated lazily in stable report/key order and evaluated only as budgets permit. The result reports total, considered, accepted, rejected, failed, and remaining pair counts; per-reason rejection counts; completed or budget-exhausted status; the budget cause; and configured range tolerance. Seed records include deterministic IDs, proposal/cell and source identities, projected frame-relative east/north, geographic coordinates, raw WGS84 inverse ranges, and wrapped true-bearing residuals.

The solver initializes from geodesic-polar intersection geometry, then refines against WGS84 inverse true bearings in the supplied projection frame. It checks nonpositive and out-of-range solutions, near-parallel geometry, numerical failures, and cell membership. A 1e-9 m range tolerance is explicitly recorded to absorb proposal-generation roundoff at the inclusive boundary; raw measured ranges are retained. The final candidate scorer remains responsible for its configured range rule, map visibility, grouping, association, and acceptance. These seeds do not certify coverage.

Tests cover an independent synthetic truth inside a cell whose center is designated land, wraparound bearings with independent geodesic direction verification, same-key and coincident-source rejection, near-parallel bearings, negative and out-of-range solutions, cell/range boundaries, rejection beyond the declared range tolerance, permutation-stable seed IDs, proposal ranking and budget priority, numerical failures, and malformed witness graphs. The dense graph test uses 400 keys from each of two reports, accounts for all 160,000 possible pairs, evaluates one pair, and checks peak Python allocation remains under 8 MiB to guard against Cartesian materialization.
