# A22 pre-LOS bound profile

The same frozen 255-candidate sample was scored twice in one process under the canonical benchmark lock. The first pass used the exact scorer for every candidate. The second pass used the prepared pre-line-of-sight bound controller and exact-scored every unresolved or unsupported case. The harness began from pinned source `17e4c4e`; commit `781b554` only corrected the preflight reader to take candidate positions from the saved exact artifact's ordered position list. The scoring and pruning logic was unchanged.

The direct exact pass took 17.906 seconds after 13.773 seconds of separately measured setup. The screened pass took 32.632 seconds, or 1.82 times the direct exact pass. Its target preparation took 12.224 seconds, bound calculation took 3.223 seconds, and exact fallback took 17.133 seconds. Independent exact validation of all proposed prunes added 1.048 seconds outside the screened-pass timing. Including that validation, the screened diagnostic took 33.681 seconds. The bound path was slower on this sample.

The controller proposed 34 prunes and independently exact-scored all 34 afterward. Every bound was at most its candidate's exact score, and none of the pruned points tied the exact best. The direct and screened results had identical best score `24.468390694319403` and tie ID `cell:74:2578`. The direct pass classified 111 candidates as invalid water, 131 as scored, and 13 as unresolved coverage. The screened path retained 111 invalid-water outcomes and 13 unresolved-coverage outcomes, exact-scored 97 candidates including the incumbent, and pruned 34.

The saved inputs were verified by SHA-256 before scoring. The selected manifest hash was `d4f2fa4812855a2f691a2ab7e9ad5035623c63abc8192106878dfd879d901a3e`, the configuration hash was `a2a306c545b05173105f5c2c7409e603d20497e8193e01c3b773321b54f1675b`, and the measurements, catalog, map, and scope-manifest hashes are recorded in `result.json`. The score-only artifacts agreed on all candidate IDs, positions, statuses, scores, best score, and tie set. No truth or held-out data were loaded.

This was a shared-host diagnostic rather than a clean latency measurement. Activity snapshots showed concurrent CPU work and two active GPU processes, with system load near 6.8 at the start and 7.0 at the screened pass. The run used one thread for OpenBLAS, OpenMP, MKL, and NumExpr. The report therefore records a slower observed result without making a formal latency claim. Per-process identifiers and user-specific paths were removed from the committed JSON; an unmodified mode-0600 copy remains in ignored local output storage.

The measured JSON is `reports/experiments/a22-pre-los/result.json`. The first invocation stopped during input validation before scorer setup or timing because the exact artifact did not repeat the position vector in each audit row. Its stdout and stderr are retained as `preflight-attempt1.*`; that failure did not consume the benchmark window. The successful run exited within the 600-second limit, left the benchmark lock free, and produced a 220 kB result artifact. The host retained 44 GiB free after the run.
