# A43 Rejected Pair-Geometry LRU Experiment

## Evaluated LRU and revised optimization proposal

A request-local LRU keyed by sorted catalog key pair was implemented experimentally in `bearing_localization/search/proposals/pairwise.py` and validated against cache-disabled output in `tests/accuracy/test_a43.py`. The experiment was then reverted from production after profiling showed that it did not help the first 64-proposal budget prefix and retained extra memory. Its exact patch is preserved at `.agent-work/outputs/a43-pairwise-profile/lru-experiment.patch`, and the before/after source snapshots and machine-readable measurements are in the same output directory.

The comparison used identical measurement SHA-256 `31e83f497e67603196ce20faeb3d2eafe6e49da832e6981b973c03d5edd8fe1f`, catalog SHA-256 `2554a1f6e574b6b9ffdefe6bb7b96636d756c9cbd87018be8f7e078738227704`, map SHA-256 `cce049c5911b39072d30f26c09947782a78e350e65a3f69c6923312fba3f9d93`, projected output origin `(-73.88006033640767, 35.18212735680013)`, and 5 km range. The map implementation source SHA-256 was `bc469ef7b37f736ae7a860aa80ffae476e6bfef765aca5813f51a58b961e8256` in both runs. The baseline pairwise source hash was `839fe01cd7b186977018493dcd2106f873f348d6c9ca4318013f81cc4f1dcd62`; the experimental LRU source hash was `997f8f9e97b05d8c90640016f64b35fbf18ee39928457e23bd272500d2f43a00`.

The complete first 64-proposal generator prefix took 5.261 seconds before and 5.340 seconds after. Both emitted exactly 64 proposals in generation-incomplete status with identical ordered proposal hash `5062bea7b768ada3d9bed43a530e18b1d27af2e7da2e0d0c18a3cb49e6bdc5fa`. Each constructed 664 local frames, which demonstrates that this budget-limited prefix did not revisit catalog pairs. RSS rose by 11.36 MiB before and 18.59 MiB after; separately, retaining 128 local frames with two transformers each increased RSS by 12.82 MiB, of which 0.68 MiB appeared in traced Python heap. The bounded LRU therefore adds memory without reducing frame construction for the observed proposal prefix. The test matrix passed 35 tests and skipped five optional hardware cases; the CPU cached/uncached parity tests ran and passed.

A narrower next proposal is to replace per-pair azimuthal-equidistant frame construction with exact WGS84 geodesic-polar calculations while leaving the generator interface and traversal unchanged. For the pair midpoint already computed by `Geod.fwd`, endpoint local coordinates can be represented by geodesic half-distance and midpoint azimuth. A local candidate `(east, north)` can be mapped back with distance `hypot(east, north)` and azimuth `atan2(east, north)` through `Geod.fwd`. This removes each pair's per-instance CRS and transformer setup. The existing input-bearing vectors, stable proposal IDs, pair order, both assignments, exact final ranges, 2R inclusive query, proposal-budget placement and emitted candidate stream must remain unchanged. No production edit for this proposal has started; it requires parity against the old frame implementation over antimeridian, high-latitude, near-parallel, and range-boundary cases, plus a finite-step check that true-north directions map to the same AEQD axes at the frame origin.
