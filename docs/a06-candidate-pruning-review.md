# Independent candidate-pruning review

This review examined candidate-bound commit b8c910c and visibility-screen commit 124dad0 in their isolated worktrees. The candidate-bound test compares the reported floor with the minimum of all partial injective assignments from the independent exhaustive oracle, using the canonical likelihood matrix only as input costs. It covers wrapped bearings, heterogeneous report and predicted sigmas, hard and unknown labels, more predicted groups than the certified minimum, and negative report-clutter and matched costs. The source-offset screen test compares exact post-visibility group counts against the production predictor after a calibrated 150 m eastward visible-feature offset.

The bearing_set_map_v1 floor is mathematically valid under its stated gates. For any candidate with at least K predicted groups and m reports, each actual assignment cardinality k has at least max(K-k, 0) unused groups. Its objective is the common baseline plus exactly m-k report-clutter terms, at least that many nonnegative group-miss terms, and k matched edges. The implementation minimizes over every k from zero through m, including k greater than K. Its sum of the k smallest report-wise floors is no greater than the sum for any selected report subset. The report-wise floor evaluates the canonical scorer at zero residual with neutral type probability one and zero predicted uncertainty. In the supported independent variance model, predicted uncertainty is nonnegative and can only widen the angular distribution, while type compatibility is at most one. Negative report-clutter costs remain valid because each cardinality is evaluated separately. Diagonal covariance is supported through report sigmas; non-diagonal covariance and calibrated common bias raise NotImplementedError and yield unresolved bounds. Non-finite results fail closed. The runtime support and visibility flags now require literal booleans, and variance support defaults to false.

The visibility screen also has a valid lower-bound argument. It ranges, offsets, and groups the same physical records as the predictor before checking line of sight. Angular groups are connected components of circularly adjacent gaps no larger than the resolution. Removing blocked members can split a component by widening gaps, but cannot join two components. Finding one clear member in a pre-visibility component therefore certifies at least one post-visibility group. Unknown observer or ray coverage and unsupported feature-model metadata invalidate the certificate. The checked calibrated-offset case confirmed that screen and predictor use the same shifted bearing, range, and target for line of sight.

The review found two integration gates. Neither candidate-bound nor visibility-screen API has a production caller in the reviewed branches; current references are definitions and tests, so pruning is not yet operational. The A14 working-tree correction replaces the shallow substring check with an explicit top-level safe metadata allowlist, recursive model-key rejection inside source attributes, and a component-specific provenance allowlist. This rejects unknown top-level model metadata and nested dimension/offset fields while retaining the A34-shaped resolved component metadata, including source latitude and longitude. Independent regressions passed for unknown top-level fields, nested model fields, supported offsets, and A34-shaped coordinate provenance. These regressions establish fail-closed screen certification; the existing predictor still applies its current nominal point geometry to those rows, and the screen returns uncertified so no pruning bound can rely on them.

The candidate-bound checks passed in the A21 worktree (3 passed). The visibility checks passed in the A14 worktree (6 passed). No benchmark outcomes or held-out data were used. These checks establish scorer-level and screen-level properties for the reviewed code, not end-to-end pruning correctness until A22 wiring and the metadata-policy change are integrated and rechecked.
