**Bounded assignment expansion proposal**

The module `bearing_localization.search.assignment_expansion` implements `expand_assignments(scorer, seed, *, config, progress_callback, result_callback)`. The `ExpansionConfig` limits each local least-squares fit to a 1000 m projected rectangle and at most 100 function evaluations, while limiting the total to 5000 deterministic branches. The `ExpansionResult` preserves the canonical seed and reports the best strictly improving exact hypothesis, completion state, budget state, serializable counters, per-branch events, and elapsed time.

Each branch pairs one currently unmatched report with one unused physical catalog record. The stable enumeration order is `(report_index, catalog_key)`. The candidate pool uses the geographic spatial index around the seed with radius `max_range_m + 2 * local_radius_m + max_calibrated_offset_m`. This is a declared local proposal window. It is not a full-box coverage guarantee, and the implementation explores no multi-record subsets or completeness certificate.

Fitting freezes the current representative assignments and adds only the branch pair for the geometric residual calculation. Report-specific sigma, catalog group uncertainty, calibrated true-east and true-north offsets, and WGS84 true-north inverse bearings are used. The seed record map, representative groups, WGS84 transformer, seed geographic coordinates, and frozen residual terms are prepared once per invocation and reused across all branches. Type labels do not enter the residual. Common-bearing calibration and all measurement covariance modes are rejected explicitly because this independent residual fit does not model them.

Every converged pose is passed back through `CandidateScorer.evaluate`. The canonical evaluation recomputes water and map coverage, line of sight, range, visibility, angular merging, catalog uncertainty, type likelihood, and complete one-to-one reassignment. An improving exact score is retained even when the proposed added key is absent from the final assignment; the event records `added_assignment_retained` for this case. Land, unknown coverage, unsupported models, solver failures, maximum evaluations, equal scores, and worse scores retain the seed. The pre-branch callback reports durable branch starts, and the post-branch callback reports each appended final event. Both callback exceptions propagate.

The focused suite in `tests/accuracy/test_assignment_expansion.py` passes fourteen tests. It covers a synthetic four-association basin rescued by a fifth branch, an unmocked production scorer four-to-five escape, clutter rejection, reassignment retention, north wrap, type-blind aliases, covariance and calibration rejection, stale and invalid seed validation, explicit insufficient assignments, budget and callback accounting, callback exception propagation, negative scores, solver and branch budget caps, one-time seed geometry preparation across multiple branches, and post-append result callbacks. No truth, evaluator, support, or known-location inputs are imported.
