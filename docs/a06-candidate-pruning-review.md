# Independent candidate-pruning review

This audit reviewed the integrated finite-candidate controller and its objective and visibility certificates at integration `6b461ee`, including the 2D height-policy fix `acdc9e1`. The review used the independent exhaustive assignment oracle in `tests/accuracy/reference_assignment.py`; it did not import the production assignment solver. The oracle evaluates every partial one-to-one assignment, including unmatched reports, unused predicted groups, forbidden edges, negative finite costs, and ties.

The `bearing_set_map_v1` objective floor is valid under its explicit gates. For a candidate with at least $K$ predicted groups and $m$ reports, an assignment with $k$ matches has at least $\max(K-k,0)$ unused groups. Its complete score is therefore no smaller than the baseline plus $(m-k)$ report-clutter costs, that many group-miss costs, and the $k$ smallest report-wise global match floors. The implementation minimizes this expression for every $k$ from zero through $m$, including $k>K$. Each report-wise floor comes from the canonical likelihood at zero residual with neutral type probability one and zero predicted uncertainty. Negative report-clutter costs remain valid because each cardinality is evaluated separately. The bound subtracts a scale-aware numerical margin and rounds downward; the controller prunes only when that result is strictly greater than the exact incumbent plus its comparison margin, so ties remain eligible.

The variance gate matches the implemented scorer. It rejects calibrated common bearing bias and non-diagonal measurement covariance, and accepts the independent diagonal-sigma model used by the scorer. Predicted catalog uncertainty is nonnegative and enters through angular variance, while type compatibility is at most one. Unsupported objective versions, malformed or non-boolean certificates, unsupported variance models, non-finite bounds, and unknown metadata produce unresolved bounds or screens and cannot prune.

The visibility screen uses the same prepared catalog records, range rules, calibrated visible-feature offsets, angular resolution, and target geometry as `predict_visible_groups`. It forms circular angular components before line-of-sight checks. Removing blocked detections can split a circular component by widening an adjacent gap, but cannot join two components, so each component with a confirmed clear member certifies at least one distinct post-visibility group. Unknown observer coverage, unknown line of sight, unsupported geometry metadata, or unexamined members invalidate a complete certificate. If an early screen reaches a potentially useful $K$ before checking all members, the controller performs a full visibility scan before pruning. The regression with a clear near member and an unknown farther member verifies that the unresolved ray forces exact fallback.

The metadata policy is explicit and fail-closed. It allows the exact resolved-component provenance schema and calibrated horizontal feature-offset pair. It rejects unknown top-level metadata and nested horizontal geometry, offset, or dimension fields. The exact nested ENC `source_attributes.height` field is treated as inert under the current 2D point geometry; it does not enter the predictor or score. An A34-shaped component fixture with `height=12.0` and source component coordinates confirms screen/prediction group-count parity. This conclusion applies to that exact nested vertical field and the implemented 2D model; other height-bearing metadata keys are not certified.

The integrated controller uses the receiving `CandidateScorer` to re-score any supplied incumbent before using its score. A caller cannot create a usable incumbent through the public initializer. Unsupported screens and bounds go through the unchanged exact scorer. Pruned candidates retain a visibility certificate and lower-bound result in their visit record. Budget exhaustion remains explicit and never receives a finite-set certificate. For generic iterators, the first probed but unvisited candidate is restored to `remaining_candidates`; the continuation regression consumes it and verifies that no candidate is lost. Finite-set certification requires iterator exhaustion and no unresolved exact evaluations. The controller does not claim completeness over continuous water positions or candidates omitted from the supplied finite set.

The independent candidate-bound tests cover wrapped bearings, heteroscedastic report and predicted sigmas, hard and unknown labels, $k>K$, negative NLLs, and exhaustive assignment comparison. The screen tests cover calibrated horizontal offsets, unknown top-level and nested model metadata, and the resolved-component provenance fixture. The integrated controller tests compare screened results with full exact scoring, preserve ties, validate incumbents, exercise early-screen unknown-ray fallback, and verify budget accounting and iterator continuation.

The final focused review command was `uv run pytest tests/accuracy/test_a21_candidate_bound.py tests/accuracy/test_a14_screen.py tests/accuracy/test_a22_screened.py tests/accuracy/test_a06_candidate_pruning_review.py tests/accuracy/test_a06_visibility_pruning_review.py -q`; it passed 57 tests. The full repository command `uv run pytest -q` passed 870 tests, skipped 31, and reported 7 passing subtests. `uv sync --locked --all-groups`, scoped Ruff checks, scoped `ty` checks, the Ruff format check, and `git diff --check` also passed.

**Decision.** Permit experimental finite-candidate pruning for the supported `bearing_set_map_v1` objective when the candidate set is explicit, the exact scorer and visibility metadata satisfy these gates, and all uncertified candidates receive exact scoring. The audit establishes correctness for the supplied finite set under the implemented model. It does not establish continuous/global optimality, performance improvement, or held-out localization accuracy; no benchmark outcomes or held-out data were used.
