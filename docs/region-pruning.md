# Conservative region pruning

This component partitions a declared projected search rectangle into cells and recursively subdivides every cell that is not safely rejected. It uses only positive, deterministic chart-aid detections. Undetected chart aids do not incur a penalty. Missing AIS vessels do not exclude a region. The observation model assumes a 360-degree view.

`maritime.search.gpu.region_prune_pipeline.prune_map_regions_gpu` joins a bounded multi-device queue, conservative evidence construction, and CuPy-batched range and bearing compatibility. The caller chooses GPU device IDs and an initial and terminal cell size. The default initial cell width is 10 km. Work is dispatched to available named devices in batches. If an explicit evaluation budget is exhausted, the result includes the complete unprocessed frontier and `complete` is false. No top-N cutoff is used.

A region is rejected only on positive evidence: a certified known-land geometry covers the whole cell interior; an explicitly complete chart catalog cannot supply the required number of distinct detections within the visibility range; or a positive marker bearing has no compatible catalog object under certified conservative bounds. Unknown map, chart, identity, position, or numerical evidence remains unresolved. A marker may be present without being detected. The optional GPU land-blocking stage may also reject a cell when a positive detection has no potentially compatible marker that can be visible from any position in that cell.

The caller must provide the actual chart-aid completeness polygon and explicitly certify that supplied catalog objects cover the entire visibility envelope. The shoreline map coverage alone does not establish chart-aid completeness. The caller must supply conservative projection-scale and true-bearing error bounds over the full envelope for range and bearing pruning. These certificates are not computed automatically. Without them the affected region remains unresolved, except where an independent whole-cell land proof is available. Uncertain positions are not treated as exact unless explicitly asserted.

A distinct-marker minimum is optional and must come from detections known to represent distinct physical aids. Uncertain and duplicate catalog identities are never silently removed from the set of possible objects. Unknown or incomplete objects should be retained as possibilities; an object set whose coverage cannot be certified must be marked incomplete.

Region geometry evidence is currently prepared on the CPU using the map polygons. CuPy performs the batched cell-to-object range and bearing calculations on the selected GPU; the scheduler coordinates batches on the CPU. Device 0 has been used for targeted correctness tests. Multi-device queue semantics have been checked using a synthetic evaluator; concurrent execution on multiple physical GPUs has not yet been verified.

This component is not connected to the coast-wide RANSAC command or the existing likelihood scorer. The existing scorer still has missed-object penalties. Do not interpret this component as a complete end-to-end deterministic-marker search until a later integration explicitly adopts these pruning semantics for final scoring and provides authoritative chart-coverage and projection certificates.

## Land-blocking proofs

`classify_land_blocking_cupy` uses known land rectangles as sufficient blockage witnesses. The GPU checks whether a verified rectangle separates the entire observer cell from every compatible exact-position marker for at least one positive detection. A center ray alone never proves a region blocked. A marker with uncertain position, incomplete chart coverage, unknown map coverage, or an inconclusive geometric proof remains possible. No unobserved marker is penalized.

Exact rectangular land components are used automatically. For irregular shoreline polygons, callers can use `derive_certified_land_barrier_tiles` to generate interior rectangular witnesses within bounded projected coordinates, then pass the returned boxes as `certified_land_barriers_en_m` to `prune_map_regions_gpu`. The helper only returns tiles strictly contained in known land and disjoint from unknown geometry, so land holes remain open. It raises if its requested grid exceeds the caller-provided tile limit. Such tiles are sufficient but not exhaustive; real occlusion may remain unresolved when no single rectangle proves it. The region queue retains that cell for subdivision.

Land witness construction and map validation currently run on the CPU. The intersection proof is performed on the selected GPU. These calculations have targeted synthetic correctness checks and witness comparisons but have not been benchmarked or verified over the complete Eastern Seaboard dataset.
