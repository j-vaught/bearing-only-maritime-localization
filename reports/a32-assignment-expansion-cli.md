# Assignment expansion in the standalone search command

The version-two standalone search command accepts opt-in CPU assignment expansion through `--expand-assignments`. The bounds are `--expansion-local-radius-m` (default 1000), `--expansion-max-nfev` (default 100), and `--expansion-max-branches` (default 5000). `--request-timeout-s` defaults to 1800 seconds when expansion is enabled. Radius and timeout must be finite and positive; evaluation and branch bounds must be integers from 1 through 100 and 1 through 5000. Numeric settings alone do not activate expansion. Expansion requires continuous mode refinement, and a GPU configuration fails explicitly because this path is CPU-only.

Search input remains truth-free. The command expands each selected refined mode deterministically, scores additions with the existing canonical scorer, and replaces a hypothesis only when its exact canonical score is strictly lower. The full candidate domain and original candidate budget counters remain intact. Expansion status, per-mode counters and elapsed time, pending modes, and request deadline state are written to the telemetry sidecar under `diagnostics.assignment_expansion`. The request clock begins at CLI entry and is checked at phase boundaries, between modes, and before each expansion branch. This is cooperative boundary enforcement; it does not preempt a phase that does not yield control.

Any expansion branch-limit or request-deadline exhaustion keeps the result ambiguous, sets `search_status` to `budget_exhausted`, records `budget_exhaustion_reason` as `assignment_branch_limit` or `request_deadline`, and leaves certification disabled. The candidate-search budget fields are preserved because expansion is postprocessing. If the request expires before candidate planning, those planned-use fields remain null and telemetry records the pending candidate search. Expansion currently has no frozen calibration binding for its processing context, so expanded runs remain ambiguous and report `assignment_expansion_not_calibrated`; this path cannot accept a fix or upgrade a certificate.

The standalone integration tests exercise a truth-free fixture after deleting its truth file, preserve complete reference-grid candidate counts, check diagnostics and calibration gating, verify request-deadline outcomes with pending work, and assert explicit GPU rejection. Focused validation passed 63 tests across A32, expansion, A20, A24, and execution-budget contract coverage. Ruff and `ty` passed for the changed implementation and A32 test module.


The separate --expand-assignments-from-coarse option selects score-ranked coarse candidates and skips continuous pattern refinement. It is mutually exclusive with the existing refined expansion option; the existing option still requires refinement. Coarse selection uses deterministic score ordering and the existing spatial de-duplication radius, and telemetry records the seed stage plus available, selected, and unselected candidate counts. The tiny truth-free command test verifies that the coarse path omits the continuous-refinement stage and remains ambiguous without a certificate. A separate coarse-seed test uses the production scorer to verify strict improvement from four assignments to five.
