# Parallel assignment-expansion audit method

The parallel producer stopped at the disk reserve with 63 completed modes and mode 48 still unknown. This audit keeps that producer status intact and builds a composite selected-mode set by taking parallel rows 0–47 and 49–63, plus the completed serial row 48. It does not describe the parallel producer as a completed 64-mode run.

Before scorer creation or truth access, the adapter verifies the serial manifest, checkpoint prefix, full event chain, source pins, and the serial audit's exact raw-file hashes. It validates the parallel rows hash, full event chain, checkpoint prefix, four worker identities, immutable package and runner sources, and the exact completed/unknown index sets. It compares parallel and serial row payloads outside timing fields, accounting for the parallel-only `candidate_branch_count` after matching it to the row counters. It requires exact branch-payload agreement in shared completed modes, checks the partial parallel mode-48 events against the serial completed mode-48 events, and checks the serial partial mode-60 event prefix against the complete parallel mode-60 ledger.

The canonical scorer rechecks both saved starts and each saved best hypothesis for all 64 composite modes. Branch-result scores from serial modes 0–59 are reused only after the corresponding mode rows and branch payloads match the serial artifacts bound by the complete serial audit. The scorer independently recomputes every exact-score parallel branch pose in modes 60–63. It retains non-exact results, pending mode-48 event counts, raw producer status, source hashes, and per-mode source choice. Truth-based geodesic and assignment metrics are computed only after the structural and exact-score checks pass.

The composite result can establish that the fixed selected set has 64 audited rows. It cannot establish full-domain completion, global optimality, a certificate, or accepted-fix status. No truth value is used to choose starts, rows, branch poses, or proposals.
