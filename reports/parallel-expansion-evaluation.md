# Independent parallel expansion evaluator review

The evaluator was repaired and reviewed against the committed producer sources. The reviewed assignment-expansion pool is b76deb56626e8b5d2a908b748ac80689ca66f77c, and the reviewed four-worker runner is a41570c525f4da6b801622366c5a601bfba09c22. The evaluator keeps the serial and parallel package and harness commits independent while requiring each artifact to prove its own immutable assignment source, runner source, and worker source hashes. It then requires matching shared scoring, assigned-input, A20, source-pin, and input-path bindings.

The event validator accepts the producer's failure phase and checks the checkpoint as an exact earlier byte and hash-chain prefix of the final event log. It validates globally interleaved events, contiguous IDs, start/result pairing, per-mode branch inventory, and durable row counts. The overlap comparison treats mode 60 as the serial partial prefix and compares branch payloads after removing only producer placement fields that are absent from the serial event payload.

The evaluator independently recomputes the score-only start choice for every returned row and compares all non-timing row fields. It rejects missing, duplicated, reordered, or out-of-scope modes and events. Worker provenance requires four unique workers, matching package and assignment source hashes, and matching scorer file hashes. A changed package commit remains rejected even when the source bytes are unchanged.

An optional complete audit is reusable only when its actual audit fields attest to all 64 completed modes, zero pending modes, completed expansion status, exact expansion event count and digest, exact expansion row and manifest hashes, all 64 mode evaluations, and exact per-mode started, result, and failure counts. The evaluator also requires the audit to remain evaluation-only, truth-independent for proposal or search selection, and certificate-free. A serial 60-mode audit therefore remains provisional and cannot certify the parallel 64-mode artifact. The existing A35 full-audit artifact, SHA 7111b39f72caf0df53e655681cb4460118b781a08bbbafdd396056774523f8b, records completed and pending modes as 60 and 4, so it is intentionally rejected for parallel certification. Missing or extra mode evaluations and branch counts remain provisional.

The independent suite contains 16 tests. It covers a valid globally interleaved fixture, mode-order corruption, missing and duplicate events, worker hash corruption, payload corruption, shortened serial prefixes, source-pin drift, a real immutable serial manifest with its failure tail and checkpoint prefix, changed package commits, incomplete audit mode counts, incomplete audit branch counts, and producer-generated events through the committed runner's append_event and _persist_state helpers. The suite passes with 16 passed in 1.47s. The committed producer's 25 focused parallel tests also pass in 15.30s with the worktree and tests directory on PYTHONPATH. Scoped Ruff and ty checks pass, and standalone pytest imports pass with the worktree on PYTHONPATH.

No real parallel output was evaluated and no diagnostic launch was performed. The launch recommendation is blocked until a parallel artifact is available and passes this evaluator. The evaluator must report provisional status whenever the complete branch audit is absent or fails any exact artifact, mode, or branch inventory check. The prior evaluator commit 93beb1fd64f34dd1da4329a2ce8845e6165adb57 was incomplete because it required an exact final event digest for the checkpoint, treated failure events as unsupported, did not distinguish legitimate serial and parallel commits, and allowed a serial audit to stand in for complete parallel branch rescoring.
