# A28 WGS84 GPU reverse-geodesic prototype

The new optional module `bearing_localization/search/gpu/geodesic.py` generates reverse-bearing observer proposals for catalog coordinates at latitudes 23–50 degrees and ranges from zero through 20 km. It uses FP64 vectorized Vincenty direct and inverse equations on CuPy, then independently checks each candidate with a device inverse solution. Inputs broadcast in NumPy order, stable IDs are retained, and positive-range proposals are processed in bounded chunks. Unsupported latitudes and distances raise `NotImplementedError`; an explicit CPU fallback uses the existing PyProj-backed solver. Zero range is marked degenerate and is never marked converged. Results are proposal geometry only; CPU exact scoring remains authoritative.

The formulas follow T. Vincenty, “Direct and Inverse Solutions of Geodesics on the Ellipsoid with Application of Nested Equations,” *Survey Review*, 23(176), 88–93 (1975), DOI [10.1179/sre.1975.23.176.88](https://doi.org/10.1179/sre.1975.23.176.88). The centralized bibliography is owned by the integration coordinator and was not edited in this branch.

Validation ran on Python 3.11 with the locked GPU extra. `ruff format`, `ruff check`, and `ty check` passed on the two owned Python files. `pytest -q tests/accuracy/test_a28_geodesic.py` passed all four tests on CUDA device 3. Device 2 had 25,088 MiB allocated and 64 percent utilization when checked, so it was not selected. The passing suite covers CPU-only import and explicit fallback, invalid input and duplicate IDs, all bearing octants, ranges 0, 125 m, 1 km, 5 km, 10 km, and 20 km, broadcast shapes, chunk sizes 1/17/16,384, seeded random catalog points, exact supported latitude limits, and longitude wrap at ±180 degrees. Independent `pyproj.Geod(ellps="WGS84")` checks compare returned observer positions and recompute inverse bearing and range.

For 1,024 seeded nonzero random proposals, all 1,024 converged and all returned positions were finite. The maximum independent inverse-bearing residual was 9.920142929331632e-8 degrees and maximum range error was 1.3708631740882993e-7 m. GPU-reported maxima were 9.918119303620188e-8 degrees and 3.990862751379609e-9 m. Processing used 34 chunks of at most 31 pairs, transferring 32,768 bytes host-to-device and 49,152 bytes device-to-host. A separate 192-case broadcast validation, including 32 zero-range cases, verified transfer counters of 5,120 and 7,680 bytes respectively. No latency or search-level performance claim was measured; the shared timing lock was not used.

The implementation does not claim complete proposal coverage for any end-to-end search and does not replace exact CPU verification. Its numerical evidence applies to the stated latitude and range domain and the tested seeded/corner inputs.
