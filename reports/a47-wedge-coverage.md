# A47 complete wedge coverage

The implementation adds an explicit complete-voting path in `bearing_localization/search/proposals/wedge.py`. The legacy `generate_reverse_wedge_proposals` function and its default budget behavior remain unchanged. The new `generate_reverse_wedge_proposals_complete` API processes sorted source chunks, keeps one vote per observation and cell, applies `max_candidate_cells` only as an accumulator budget, and ranks all accumulated cells after processing. The geographic wrapper `generate_geographic_reverse_wedge_proposals_complete` preserves local tile and geographic metadata.

The batch geometry evaluates source rows against half-cell ray samples and the nine-cell halo. It falls back to the scalar geometry for integer-range rows and rows near distance, angular, or grid-boundary decisions. Small complete fixtures matched the scalar reference exactly for candidate IDs, vote counts, source counters, and status across 100 randomized cases. The existing 64-cell legacy prefix tests remain passing.

The earlier per-source vectorized prototype was rejected because the capped 64-cell workload took 0.317 seconds versus 0.262 seconds for the scalar implementation. It was removed. The new complete path batches enough source rows to amortize array setup while retaining scalar boundary authority.
