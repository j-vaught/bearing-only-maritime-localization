# B-location suite

J.C. Vaught.

The runner simulates authoritative B1 through B24 in order and searches only frames with more than 15 detected positive physical-aid reports using the corrected Charleston sensor configuration and the complete original Eastern Seaboard rectangle. The existing seed 11 applies to every location. The simulator retains its keyed noise and detection streams. The canonical chart catalog represents colocated chart components as one physical object. Vessel clutter remains outside the marker-only search and never contributes to eligibility. The explicit minimum of 16 enters the saved settings provenance and is checked after simulation and before any search process starts. Cases with 15 or fewer aid reports receive a persistent skipped status.

The supervisor loads the saved map/index and canonical object sidecar once, with rebuilding disabled. It reads the raw simulator map layers and canonical scene once. Each simulator call clips those layers around the observer and every in-range physical target with a positive 1 m margin, following the saved corrected Charleston generation. Every simulated sight line lies strictly inside that crop, so the same layer intersections are retained without constructing a global simulator overlay. One persistent fork child inherits the prepared world and uploads GPU buffers to devices 0 through 2 on its first eligible request. Later requests retain those buffers and their owner threads. The supervisor never imports the CUDA array runtime. The suite preserves the 1 m terminal size, 512-cell processing batches, and 2 GB workspace ceiling, while increasing root packets from 8 to 128. Profiling samples every 10 batches and starts a fresh report for each site. Search time includes first-request device construction, traversal, and lifecycle finalization. Worker startup, shared preparation, simulation, selection, post-freeze accuracy, and total site duration are reported separately. Actual per-device reuse is recorded in the search summary. See [Persistent GPU search workers](../../resident-persistent-session.md).

The search child receives the prepared world and fixed search configuration once. Subsequent requests contain measured aid bearings, their bounds, and the output directory. It searches every root in the declared rectangle without candidate preselection. The existing saved-output selector chooses minimum absolute bearing residual, with east then north tie breaking. The estimate file is hashed and frozen before the evaluator reads the observer coordinates and computes the WGS84 geodesic error. No alignment, fit, or truth-based refinement is performed.

Each search has a 600-second timeout. Selection has a 120-second timeout. Traversal stops at 50 million evaluated cells or 2 million terminal cells. A worker failure or timeout poisons the service and stops its process group, escalating from SIGTERM to SIGKILL when necessary. The service cannot automatically restart. Normal suite completion closes the worker and checks for remaining descendants. GPU occupancy and at least 20 GiB output capacity are checked before each site. Only the exact owned worker process is permitted to retain GPU allocations between sites. Every attempted site retains a persistent result, including invalid observers, empty frames, incomplete searches, timeouts, and absent estimates. The solver accepts at most 256 positive aid reports. Smaller nonempty frames remain subject to the same search and resource limits.

Completed sites are skipped on resume only when the complete source, data, settings, observer table, seed policy, and resource-limit provenance matches. Failed and partial attempts are preserved and retried in new attempt folders. Solver frontier snapshots are retained, while an interrupted individual search restarts from its full rectangle. The authoritative B24 latitude is 25.76 and longitude is -80.175. The runner never substitutes the earlier 35.76 value.

Run the scoped checks with `uv run --extra gpu ruff format docs/verification/b-location-suite`, `uv run --extra gpu ruff check docs/verification/b-location-suite`, `uv run --extra gpu ty check docs/verification/b-location-suite`, and `uv run --extra gpu python docs/verification/b-location-suite/test_runner.py`. A dry run uses `--dry-run`. The simulation-only preflight uses `--preflight-only` and verifies exact B17 marker-bearing parity against the saved corrected frame before any suite search can launch.

Run or resume the detached supervisor with `.venv/bin/python -u docs/verification/b-location-suite/run_suite.py --output runs/b-location-suite-aids16-20261029`. Keep its standard output and PID in the output folder. Inspect `status.json`, `results.csv`, `results.json`, `aggregate.json`, and each site's `result.json`. The manifest records hardware, hashes, limits, data counts, and CPU roles. Cache fingerprints before and after the suite must remain identical.

For map-loaded timing at every site, pass `--preload-gpus` to the supervisor. The service uploads its map and catalog before the first timed request and records this duration in `gpu-preload.json`. Preparation seeds no cells and performs no localization search. Per-site reuse diagnostics must then be true from the first site onward.
