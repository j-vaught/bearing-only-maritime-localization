# B-location suite

J.C. Vaught.

The runner evaluates authoritative B1 through B24 in order using the corrected Charleston sensor configuration and the complete original Eastern Seaboard rectangle. The existing seed 11 applies to every location. The simulator retains its keyed noise and detection streams. The canonical chart catalog represents colocated chart components as one physical object. Vessel clutter remains outside the marker-only search.

The supervisor loads the saved map/index and canonical object sidecar once, with rebuilding disabled. It reads the raw simulator map layers and canonical scene once. Each simulator call clips those layers around the observer and every in-range physical target with a positive 1 m margin, following the saved corrected Charleston generation. Every simulated sight line lies strictly inside that crop, so the same layer intersections are retained without constructing a global simulator overlay. Each sequential fork child inherits the prepared world and uploads fresh GPU buffers to devices 0 through 2. The supervisor never imports the CUDA array runtime. The unchanged optimized search API, 1 m terminal size, 512-cell batches, 8 roots per task, and 2 GB workspace ceiling match the saved Charleston configuration. Profiling samples every 10 batches. Search time includes device construction and traversal. The shared preparation duration, simulation, selection, post-freeze accuracy, and total site duration are reported separately.

Search children receive only the prepared world, measured aid bearings, and truth-free settings. They search every root in the declared rectangle without candidate preselection. The existing saved-output selector chooses minimum absolute bearing residual, with east then north tie breaking. The estimate file is hashed and frozen before the evaluator reads the observer coordinates and computes the WGS84 geodesic error. No alignment, fit, or truth-based refinement is performed.

Each search has a 600-second timeout. Selection has a 120-second timeout. Traversal stops at 50 million evaluated cells or 2 million terminal cells. Timed-out process groups receive SIGTERM followed by SIGKILL when necessary, and live descendants are checked before the next site. Existing GPU occupancy and at least 20 GiB output capacity are checked before each site. Every site retains a persistent result, including invalid observers, empty frames, incomplete searches, timeouts, and absent estimates. The solver accepts at most 256 positive aid reports. Smaller nonempty frames remain subject to the same search and resource limits.

Completed sites are skipped on resume only when the complete source, data, settings, observer table, seed policy, and resource-limit provenance matches. Failed and partial attempts are preserved and retried in new attempt folders. Solver frontier snapshots are retained, while an interrupted individual search restarts from its full rectangle. The authoritative B24 latitude is 25.76 and longitude is -80.175. The runner never substitutes the earlier 35.76 value.

Run the scoped checks with `uv run ruff format docs/verification/b-location-suite`, `uv run ruff check docs/verification/b-location-suite`, `uv run ty check docs/verification/b-location-suite`, and `uv run python docs/verification/b-location-suite/test_runner.py`. A dry run uses `--dry-run`. The simulation-only preflight uses `--preflight-only` and verifies exact B17 marker-bearing parity against the saved corrected frame before any suite search can launch.

Run or resume the detached supervisor with `.venv/bin/python -u docs/verification/b-location-suite/run_suite.py --output runs/b-location-suite-20261029`. Keep its standard output and PID in the output folder. Inspect `status.json`, `results.csv`, `results.json`, `aggregate.json`, and each site's `result.json`. The manifest records hardware, hashes, limits, data counts, and CPU roles. Cache fingerprints before and after the suite must remain identical.
