# Independent assignment expansion review

**Scope.** The review exercised the bounded single-addition expansion contract on small synthetic geographic scenes. The scenes were generated from catalog records and angular measurements, and each seed came from the canonical scorer. No truth input, accepted fix, held-out input, large diagnostic, or GPU run was used.

**Implementation reviewed.** The expansion tests ran against source commit `8631d37` on `accuracy/assignment-expansion`, including the prepared-seed geometry cache and durable post-append result callbacks. The companion runner was read and tested at commit `67b48e4` on `accuracy/assignment-expansion-runner`. The runner consumes exactly 64 completed assigned-refinement rows, revalidates both saved starts, selects the deterministic lower-score start with label tie breaking, keeps the canonical lock, checks the 40 GiB reserve and 50 MiB output cap around every branch event, records resource and branch failures, and writes `full_domain_complete=false` with `certificate_scope=none`. The revised manifest records the loaded package commit and assignment-expansion source hash separately from the assigned input package pin. The preflight report records 22,000 candidate branches across the 64 modes without executing them.

**Adversarial coverage.** The ten focused tests cover stale score or assignment rejection, explicit covariance rejection, callback ordering and exception propagation, durable result-callback ordering with mutation isolation, exact branch-budget accounting, stable catalog-key ordering across catalog permutations, one-to-one and angular-group duplicate handling, clipped local bounds and the `max_nfev` limit, canonical assignment retention when a proposed key is not retained, and independent verification that residuals use WGS84 true-north bearings with report-specific sigma and catalog uncertainty combined in quadrature. The owner suite also includes an unmocked production-scorer four-match seed that recovers the fifth association with the canonical scorer.

**Verification.** The focused suite passed with `10 passed in 0.44s` against `8631d37`. The owner expansion suite passed with `14 passed in 0.44s`, and the runner suite passed with `13 passed in 0.47s` at `67b48e4`; Ruff checks passed for both owner source/test pairs. The review suite was run from `/tmp` with `PYTHONPATH` pointing to the owner source and review worktrees so it did not accidentally import an incomplete local package. No implementation defect was reproduced by these tests. The runner source still contains two stale exception strings that say `20 MiB` although `MAX_OUTPUT_BYTES` is 50 MiB. This is a diagnostics-text defect and should be corrected before the run so failure messages agree with the manifest cap.

**Disposition.** The expansion implementation and revised callback persistence are ready for coordinator integration from the reviewed source state. The runner provenance separation and immediate branch-event persistence are structurally correct at `67b48e4`; correct the stale 20 MiB text before execution. The production diagnostic remains an explicitly incomplete heuristic run. Its execution should preserve the recorded source and input hashes, the 64-mode artifact, the branch counters, and every failure or resource outcome in the durable output.
